# Paper Notes 文档与来源规范

## 定位与兼容

优先采用用户指定库或当前工作区；核对 `data/categories.yml`、`scripts/generate-index.mjs` 的实际校验规则、`README.md` 和已有笔记，不依赖站点模板文件。此 skill 可被其他 agent 直接读取，不依赖特定插件、全局绝对路径或 CCFA sibling skill。按实际环境使用全文获取、网页检索和 PDF 读取能力。

论文与主题调研是两条独立轨道。单篇精读上传后的目标路径为 `papers/<category>/<slug>-<year>.md`，从 `data/categories.yml` 的 `papers` 列表推荐主领域分类，标签用于跨方向检索。单篇笔记包含背景调研，仍属于论文轨道。待审阅成品沿用用户指定位置，否则存入库内 `.tools/paper-drafts/<slug>-<year>.md`，不预先写入正式目录或修改分类配置。

围绕问题综合多篇文献的报告属于主题调研轨道，目标路径为 `research/<category>/<slug>-<year>.md`，分类来自同一配置的 `research` 列表。两条轨道的分类各自维护，同名分类可以分别存在；`主题调研` 是轨道，不是为了区分文档类型而塞进论文轨道的分类。报告按研究问题组织，不套用单篇论文的八部分骨架、作者或发表场所；`year` 填报告年份。

每次按实际配置推荐分类。目标轨道没有合适分类时，交接建议的 id、名称和范围，由 uploader 在已获授权的入库流程中创建；reader 不为草稿提前增加正式分类，也不自行恢复用户已删除的类别。

同一论文先核查 DOI、arXiv ID、原始链接、标题及版本，避免重复。更新已有笔记时，先在待审阅位置准备新版本，保留手写批注和不能确认来源的既有内容，获确认后再替换正式稿。无法定位库时，可在已授权的输出位置生成独立 Markdown，不声称已入库；上传交接时再确定必要的目标信息。

## 发表来源与日期核查

打开出版方文章页、官方会议论文集/录用页、OpenReview 的公开决定页和预印本版本历史等对应原始记录。搜索结果卡片仅用于定位。以实际读到的记录为依据，交叉核对标题、作者与 DOI/arXiv ID，不将同名论文或内容有实质差异的版本合并。

- **发表刊物或会议**：写出完整名称、常用简称、届次/年份，以及影响判断的 track 或 Workshop。期刊可补卷期、页码/文章号、DOI。会议主会与附属 Workshop 分开；OpenReview、arXiv 是平台，不自动代表正式发表场所。
- **发表状态**：区分正式发表、已录用未核实正式出版、仅预印本、在审和未知。“投稿至”“under review”不能写成已发表；查到预印本并不能证明后来没有正式版本，需记录核查截止日期。
- **最早公开时间**：提取同一研究最早可核实的公开版本及平台，例如 arXiv v1；核对是否存在更早的可验证公开版本。可称“目前可核实的最早公开日期”，不保证排除了所有未索引来源。修订日期不能代替首次公开日期。
- **正式发表时间**：单列可核实的在线发表或论文集出版时间。不要拿私有投稿时间、接收时间、会议举行时间或 DOI 注册时间冒充发表时间。只有年份或月份时保留该精度，不能补造月日。
- **所读版本**：写明本次分析使用的 PDF/HTML 版本及其对应日期。若预印本和正式稿的方法不同，按实际读到的版本描述，指出与书目年份的关系。

来源冲突时列出两个记录及各自含义；无法裁定就标为未核实，不靠看似精确的日期掩盖缺口。无法联网或缺少公开记录时仍可生成供审阅的笔记，但明确相关字段未核实。历史思路重建以方法最早公开版本为边界；最早日期未核实时，写明采用的临时边界及不确定性。

正文开头用紧凑的“论文来源”表展示场所、状态、最早公开时间、正式发表时间、所读版本与核验链接。场所与状态可合并一行，链接直接嵌入信息列；仅保留影响身份或版本判断的说明，不把核查经历写进表格。表中的年份不一定相同，不能为整齐强行合并。

## 代码仓库与项目主页

对每篇论文主动查找这两类资源，不能只等待用户提供链接。优先检查论文首页、正文/附录中的链接、预印本记录、出版方页面及作者公开的项目入口；必要时以准确论文标题、作者和 code / GitHub / project 等词检索。

- **代码仓库**：核对仓库说明中的论文标题、作者、引用信息，以及论文或作者项目页对该仓库的指向，确认它对应当前论文。官方代码写入 `code`；第三方复现可在正文另列并注明身份，不能作为官方链接填入。仓库只发布了占位说明、模型权重或部分实现时，明确实际公开范围，不声称已开源完整代码或可直接复现。
- **项目主页**：核对页面与论文及作者的对应关系，写入 `project`。作者个人首页、实验室首页和聚合检索页不能替代具体项目主页。代码仓库与项目主页分别核实，不根据其中一个链接臆造另一个；若官方明确以仓库 README 作为项目主页，可以使用同一地址并说明。
- **链接状态**：打开目标页核查实际内容与跳转后的地址，使用稳定的原始入口，避免搜索结果 URL、临时下载链接或凭据参数。区分“未找到”“作者明确表示尚未公开”“官方已提供但访问失败”和“未联网核实”；检索未找到不等于资源不存在。没有可靠地址时字段留空，在正文写明状态，已知但暂时无法访问的官方链接可在正文附来源与访问说明。
- **展示与交接**：将有据可查的链接同时填入 frontmatter 的 `code`、`project` 和开头来源表，表中附核验依据；多个官方仓库可在正文说明各自用途，`code` 选择主要实现入口。已有链接更新时保留仍有效的版本信息。提取或阅读代码不等于安装、执行或验证了实现。

## Frontmatter

以 `assets/note-template.md` 为技能内部骨架；示例分类也须对照当前配置确认，其他示例标题、年份、日期、链接、摘要和提示语均须替换或移除。必填字段：

| 字段 | 要求 |
| --- | --- |
| `title` | 核实的论文正式标题，非空字符串；功能性中文解释可放在正文标题或导语 |
| `year` | 论文所采用书目版本的年份，整数；不得用阅读年份代替，不确定就先核查 |
| `category` | `data/categories.yml` 的 `papers` 列表中的合法 id；拟新增分类在草稿交接中注明，正式入库前须先创建 |
| `tags` | 非空字符串数组，使用稳定的主题术语 |
| `summary` | 一句话概括具体问题、关键机制与适用范围，不写夸大评价 |

推荐 `type: "paper"`、`shortTitle`、`date`、`authors`、`paper`、`status`。`type` 可省略，由正式文件目录推断；填写时必须与目录一致。分类 id 必须在论文轨道定义，文件所在分类目录也须与 `category` 一致。`date` 是笔记编写/更新日期，使用 `YYYY-MM-DD`；论文版本与检索截止日期另写在正文。`paper` 使用已核实的稳定公开地址；本地未公开稿不虚构 URL。`authors` 是已核实作者的字符串数组，`code` 和 `project` 仅填验证过的地址。未请求时不生成主观 `rating`；部分阅读使用 `status: "partial"`，完成全文分析后可用 `status: "read"`。`status` 仅表示目标论文的阅读状态，不表示外部检索、实验或构建已经完成；这些覆盖范围和缺口须分别写明。

单篇笔记另外保留以下发表来源字段；它们不会改变现有生成器的必填校验。未知值用空字符串、空数组或 `unknown`，在正文解释缺口。日期始终使用引号保留字符串和精度。

| 字段 | 约定 |
| --- | --- |
| `venue` | 核实的会议/刊物名称、年份及必要的 track；无正式场所则留空，在正文说明预印本平台 |
| `venueType` | `conference`、`journal`、`workshop`、`preprint` 或 `unknown` |
| `publicationStatus` | `published`、`accepted`、`preprint`、`under-review` 或 `unknown` |
| `firstPublished` | 最早可核实的公开日期，`YYYY-MM-DD`、`YYYY-MM` 或 `YYYY` |
| `publishedAt` | 正式发表日期，保持来源精度，未核实则留空 |
| `publicationSources` | 已核实的原始来源 URL 数组，正文说明每个 URL 支持哪个字段 |

这些扩展字段目前不会自动显示在首页或索引；必须同时写入正文的来源表。主题调研报告整体没有单篇论文的发表场所，勿套用这些字段；可在各篇参考文献中保留相应信息。

不得为了通过校验编造书目信息。必填事实无法确定时先保存在库外的已授权草稿位置，并说明尚不能成为正式入库稿。

YAML 字符串含冒号、引号等字符时正确引用或转义。当前生成器把 `title`、`shortTitle`、`summary` 直接写入 Markdown 表格和链接，避免这些显示字段包含换行、未转义的 `|`、破坏链接的方括号或原始 HTML；必要时使用安全转义，并核对渲染结果。

## 正文与引用

正文开头用紧凑来源表记录论文身份、所读版本与原文入口，用一行说明历史知识和本次检索截止日期。阅读覆盖简述实际采用的材料；缺失全文、版本差异等影响理解的缺口集中说明一次，不列逐文件核查过程或未执行事项清单。正文按八部分组织：研究问题与价值、从前人工作走到 idea、核心 intuition、方法与简单例子、实验问题与关键数据、take-aways、脆弱假设、follow-up idea。相关工作与思路推演合并成因果链；原文确有核心数学推导时融入相应方法步骤。末尾列正文实际引用的完整参考来源。

采用标准 Markdown、普通表格与站点已支持的 LaTeX 数学语法：行内 `$...$`，独立公式 `$$...$$`。未验证站点支持前，不依赖 Mermaid、专属引用语法、对话引用 token 或嵌入式组件。HTML 可能被 VitePress 当作组件解释，数学比较符和类型占位符放在公式或代码中。

给目标论文编号 P0，相关来源按首次使用顺序编号 P1、P2 等。正文用 `[P0](https://真实来源)` 一类普通链接并注明必要的章节、图表或公式；相邻数句共用同一依据时在段末引用，不逐句重复。文末记录标题、作者、年份/版本与链接；支持对象不清楚或只读了部分材料时补简短说明，不给每条引用附检索日志。只引用实际查阅的材料。无法公开链接的用户材料标明文件名和可核对页码，不泄露机器绝对路径。

实验表直接填写从论文核实的少量关键数据，注明比较设置、指标单位、优劣方向，以及理解比例或可靠性所需的分母、样本数或误差信息；原文未报告的内容明确说明，不能补造。表题或表后附原始出处链接与必要定位，避免结果或结论栏只有“Table 1”“Fig. 4”等引用。不同设置的数据分开呈现，不能靠并列数字暗示公平比较。方法中的简化示例与实测结果分开，示意数值不进入实验结果表。

涉及外部图片时优先自行解释其信息并引用原图，不默认复制整页或图。确有必要的本地附件放在库已采用的位置，以可解析的相对路径链接；不能留下仅本机有效的临时路径。

## 待审阅保存与交接

先检查用户当前改动，再保存待审阅稿。`.tools/paper-drafts/` 由本库忽略并排除页面构建；在其他库使用时先核查相同约定，没有排除就改用站点源目录外的已授权草稿位置。源 PDF、提取文本、临时记录和未确认稿不能混入 `papers/`、`research/` 或成为公开页面。不要手改生成的首页、论文索引、主题调研索引、标签索引和 `.vitepress/generated/*`。

交付前检查 YAML 字段、分类、来源表、引用链接、公式和示例值是否已经替换。需要完整站点预览或索引测试时，在隔离临时副本中加入候选文件并运行仓库命令；检查结果用于审阅，不提前改动正式库。无法验证时在交付中说明具体缺口。本流程无需 Python；若其他工具需要 Python，遵守目标项目的 Conda 环境约定。

提供完整初稿的可预览链接，按 SKILL.md 的“初稿审阅与上传交接”处理修改意见与上传意愿。后续问答属于阅读阶段，不要求每轮重写笔记或询问上传。用户只要求独立 Markdown 时仍交付可审阅文件，不称为已入库；用户明确不上传时接受选择，不重复追问。

收到明确上传请求后，交给 `paper-library-uploader`：传递初稿或最新稿及版本、论文轨道、建议目标路径与分类（包括拟新增项）、元数据与来源、附件、替换关系、相关会话或讨论记录、已并入与待并入的补充和纠正、未解决问题及授权范围。上传 skill 先总结有价值的讨论并融入相应章节，再负责正式文件写入、索引生成、构建以及授权范围内的提交/推送/部署。可选的 `<slug>.discussion.md` 放在排除发布的草稿目录；原始聊天、私人信息和确认消息不能写进公开论文正文。
