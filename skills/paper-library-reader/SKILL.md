# Paper Library Reader

帮助用户高效阅读新文献，掌握研究问题、idea 的来由、方法如何工作以及实验说明了什么。先围绕一条研究主线生成八部分 Markdown 初稿，再通过持续问答补足用户理解所需的细节。初稿保持精炼，讨论按问题深入；最终由 uploader 将有价值的讨论融入笔记并发布。生成笔记和讲解本身不包含实验执行、算力购买或上传发布。

## 工作流程

1. 确认论文身份、版本、发表来源和目标库。核实发表刊物或会议的名称、年份、主会/Workshop/track、发表状态、最早公开时间及正式发表时间，区分预印本和正式版本；主动查找论文对应的官方代码仓库和项目主页，有可靠链接时分别写入 `code`、`project` 字段，并在笔记开头展示可点击链接及核验来源。按 [文档与来源规范](references/library-format.md) 处理日期精度、缺失和冲突。用户给出标题时先核实同名论文，只有歧义影响任务时才询问。从会话与目录定位论文库，不写入猜测的路径。
2. 获取并阅读全文、支撑核心 claim 的附录、关键图表；必要时核对官方实现。抽取文本后，对公式、图、表或符号歧义查看原页面。检索结果摘要、二手解读和旧笔记只能帮助定位，不能替代原文。
3. 动笔前在工作记录中走通主线：已有方法靠什么起效 → 在什么条件下遇到瓶颈 → 这对新方法提出了什么要求 → 哪条已有知识提供了可行的解决途径 → 由此得到什么候选 idea。每次转折要解释因果关系，不能只罗列几篇相关工作后宣布“把它们结合”。再核对本文如何具体实现、哪些实验检验了它。区分借用的成熟技术、本文关键改动和配套实现；系统论文可以贡献组件间有效的衔接，不必虚构单一新算法。
4. 按下文的两个时间边界补充外部文献。优先论文原始版本、出版方、作者项目和官方代码；引用前打开并核实对应内容。遇到难点主动检索，不靠记忆补出定理、实验结果或引用。
5. 按 [阅读与分析规范](references/analysis-guide.md) 和 [笔记骨架](assets/note-template.md) 写八部分：研究问题；从前人工作到 idea；核心 intuition；方法与简单例子；关键实验；take-aways；脆弱假设；follow-up idea。思路推导先于方法讲解。方法先过一遍论文的主要步骤，原文有核心数学推导时融入对应步骤，随后用一个简单例子完整走通。实验直接展示核实过的关键数据表。
6. 先做主线与删减检查，再核对证据、适用边界、frontmatter、引用和公式，保存待审阅成品。需要构建验证时使用隔离副本，不把待审阅稿写入正式 `papers/` 或更新正式索引。未完成的检索、推导、运行或构建必须如实报告。
7. 按下文“初稿审阅与上传交接”展示完整初稿，询问修改意见和上传意愿。用户继续提问时进入讨论阶段；明确要求上传时，将初稿及后续讨论交给 uploader 整合、检查并发布。

## 初稿后的讨论

- 后续提问属于同一篇论文的阅读过程。直接回答当前问题，必要时回到原文、附录、代码或相关工作核实，再用必要的推导或例子解释。无需每轮重写八部分笔记，也不重复询问是否上传。
- 保留对最终笔记有价值的讨论成果：用户卡在哪里、解释如何补上理解缺口、哪些旧表述已纠正、证据在哪里，以及哪些问题仍未解决。已经被后续证据推翻的回答不能作为结论继续交接；用户的提问与 agent 的回答本身不构成论文证据。
- 用户明确要求修改初稿时，在同一草稿中更新并展示相关变化；其余补充可以留到上传阶段统一整合。交接时分清已并入与待并入的内容，避免重复。
- 长对话或需要跨任务交接时，可在草稿旁保存 `<slug>.discussion.md` 精简记录，保留上述成果及来源定位，覆盖已纠正的误解，不复制聊天流水账。上下文已足够时无需额外文件。记录放在不参与发布的草稿目录，属于交接材料。

## 初稿审阅与上传交接

**先展示初稿供用户阅读和讨论；用户要求上传时，由 uploader 整合讨论并发布。** 这是用户指定的分工。

- 初稿完成后，优先打开可预览的 Markdown 并提供完整文件链接，附简短导读、已核实的发表来源与关键缺口。询问需要修改的地方和是否上传；用户已明确选择继续讨论或暂不上传时，遵从该选择。
- 只有“看看”“修改一下”、提出论文问题或认可某个解释，不构成上传授权。未获授权时保持草稿状态，不写入正式 `papers/`、提交或推送。上传询问默认放在最终答复中，不在初稿写完和检查前索取许可。
- 用户审阅初稿并完成若干轮讨论后说“上传”，其范围包含将相关讨论中的解释、纠正和补充融入初稿，再执行发布；无需让用户先自行整理，也不因这种常规整合重复要求审批。超出已讨论范围的新结论或影响核心结论的未解冲突，由 uploader 先完成可审阅稿，再澄清具体阻塞点。
- 交给 `paper-library-uploader` 时，传递初稿或最新稿路径、论文版本、来源、分类、附件、替换关系，以及相关讨论、已并入与待并入的补充、纠正和未解决问题、用户对篇幅及内容的最终偏好、上传目标与授权范围。该 skill 缺失时可按相同分工执行已授权动作，不宣称已调用不存在的能力。

全文无法取得时，继续处理可核查材料，标记为部分阅读稿，保留未知位置。不能根据摘要编造方法、数学、实验或作者思路；仍可写独立成立的背景，但不得宣称完整精读已经完成。用户禁止联网时尊重限制，明确哪些背景和新颖性尚未核查。

## 两个时间边界

- **重建思路的历史边界**：以该方法最早公开版本的日期为上限，研究背景和第 2 节的前人工作、推导前提均受此约束。同期独立工作注明时间关系，后续进展放在脆弱假设与 follow-up 部分。后来的教程可帮助今天解释术语，但不是作者当时的 inspiration。目标论文新增的失败观察、模块、定理和实验结果不能偷偷作为推导起点。
- **评估后续研究的当前边界**：脆弱假设与 follow-up 部分检索到本次实际检索日期，包含后来复现、反驳、扩展和最接近的工作。记载日期、检索范围和直接竞争方案；不能把旧论文的未解问题自动认作今天的空白。

## 写作要求

- **完整阅读，选择性呈现。** 正文默认约 3000–5000 中文字，作为编辑参考，不凑字数。优先把篇幅给从已有知识到 idea 的因果连接、方法讲解和实例。必要推导可以展开，但先删重复、旁支和实现细枝末节；不能为缩短而省掉关键推理步骤或理解实验所需的数据。脆弱假设和后续方向不扩写成研究计划。
- **每项信息有一个主要位置。** 前人工作与思路推导合为一条论证，intuition 压缩其本质；方法先整体讲解，再通过简单例子展示关键步骤如何发生作用；数学仅在方法需要的位置解释。实验提供结果与判断，take-aways 提炼可迁移认识，其余章节不再复述整个流程。
- **先给问题和答案，再解释连接。** 每节让读者清楚它在回答什么。思路推导按已有知识到候选想法的顺序推进，不提前给出论文模块再寻找理由。方法术语不能替代解释：要说清什么发生变化，以及它为什么影响结果。导语只用两三句交代核心问题和工作定位，具体方法在思路推导之后展开。
- **用取舍体现重点。** 通常选 2–4 个决定性实验问题，直接摘录或整理关键对照数据。表格同时交代设置、指标、单位与必要分母，让读者不打开论文也能判断结果。原图表编号可留在表注或来源链接中，不用“见 Table 1 / Fig.4”代替数据和解释。数学由原文实际推导决定，不另开通用算法教程。
- 提炼用户所指 Andrej Karpathy、Kaiming He 的清晰讲解取向：具体问题起步，抓住机制，用直观例子连接形式化表达，对证据保持克制。不模仿口头禅，不虚构他们的观点或背书。
- 使用自然连贯的中文。每段推进一个事实、机制、条件或推理；术语首次出现解释，英文仅在更精确时保留。删除“意义重大”“广泛应用前景”等缺少对象和依据的套话。
- 直接围绕研究问题、机制和证据展开，不添加“原文：”“文献：”“推断：”“猜测：”等段落标签、信息分类图例或“信息类型”表格列。也不要逐段重复“论文认为”“我们推测”作为替代前缀；归属和不确定性确实影响理解时，再自然地融入句子。
- 保留支持具体论点的引用和必要的定位。来源放在对应段落末或数据表注，避免阅读正文时被编号打断。尚未验证的解释和教学例子在首次涉及处自然交代，不把设想写成已验证结果，不把教学补步归给作者。
- 阅读版本和影响理解的材料缺口集中简述一次。影响核心 claim 的限制紧邻结论保留；需要深入分析的依赖条件放在脆弱假设部分。不要给每段补一句“这不能证明……”或反复提醒未运行、未验证、不能推广。检索日志与自检结论留在工作过程中，不进入正文。
- 不用“不是……而是……”及类似低信息量对照；直接说对象、机制和差异。少用破折号、装饰性引号、机械排比。列表用于步骤，表格用于真正需要比较的内容。
- 具体说明研究对象、设置、约束、对比基线和结论范围。可读性来自解释清楚，不能靠删去限制条件或把猜测写成事实实现。
- 从前人工作到 idea 的论证是基于历史证据的动机解释，不声称恢复作者的私人思考记录。真实作者自述应引用出处；缺少证据的连接用适当语气表达，不能为追求流畅捏造唯一必然的设计路径。

## 交付前检查

- 读完思路和方法，能复述“已有机制 → 具体瓶颈 → 设计要求 → 可行途径 → 候选 idea”，每个转折有解释。借用技术与本文贡献没有混淆，主线未被术语和模块清单代替。
- 做一次删减：同一机制或限制是否讲了多遍？删去某段是否影响理解或判断？不影响的删除。方法概览与例子分别承担解释和演示，不逐句重复。
- 八部分齐全，材料不足项指出具体缺口；未再单设数学章节或要求复现实验计划。
- 思路推导的每个起点独立于目标论文贡献成立；不能只由“已有 A、已有 B”跳到“把 A 和 B 结合”。证据不足时保留真实断点，不编造 inspiration。
- 方法先覆盖主要步骤，再给简单例子；例子输入、中间变化、输出能串起来，真实材料有来源，教学简化清楚且没有冒充实测。
- 原文有关键推导时在方法相应步骤解释目标、符号、依据与结果；原文没有时不额外制造推导或数学小节。
- 原文有可核实量化结果时，关键实验数据已直接呈现在表格中，设置、单位、指标方向和必要的样本分母清楚；不同协议不混成同一比较，结论没有超出数据。
- 脆弱假设解释核心机制依赖什么、为何脆弱及失效后果，不附一周安排或复现方案。Follow-up 简要比较最接近工作，明确新机制与尚待验证的差异。
- 叙述连贯，没有段落信息标签或自检过程说明；引用支持相邻论点，必要的不确定性自然表达，没有虚构数值、作者动机、实验执行或新颖性保证。
- 发表刊物/会议、状态、最早公开时间、正式发表时间及其来源均已核实或明确标为未核实，没有把会议举行日或投稿日当作发表日。
- 已查找代码仓库和项目主页；可靠链接同时保存在 `code` / `project` 与正文来源表中。缺失或未核实状态如实说明，第三方复现没有冒充官方代码，仓库存在没有被写成已运行验证。
- frontmatter、推荐分类、路径、链接和公式符合目标库；完整初稿已交付审阅，上传意愿已按当前阶段处理，未获上传授权的稿件没有进入正式库。交接时包含后续讨论成果及尚未解决的问题。
