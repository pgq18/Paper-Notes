# 动作分块策略何时重新规划：自适应执行窗口与闭环验证

动作分块策略一次预测多步动作，却仍需决定何时重新看环境。现有工作主要解决两种问题：在动作块生成后选择执行多长，或在执行过程中检查新观测并提前中断。前者依据当前信息预先分配反馈频率，后者能响应随后出现的变化。围绕 BCP 寻找相近方法时，应先区分这两种接口，再比较选择信号、学习目标和计算代价；仅凭“自适应”“停止”“闭环”等名称，很容易把不同机制放在一起。

本文检索截止 **2026-10-20**，范围包括自适应执行窗口、继续／重规划、执行验证与前缀价值学习。AAC 使用已核实的 CVPR 2026 正式版本，其余按下表所列 arXiv 版本讨论，未将未核实的录用信息写成正式发表。日期是首次 arXiv 提交时间；版本日期另列。跨论文的模型、任务与成本口径不同，本文比较机制，不作数值排名。

## 1. 最关键的区别：决定窗口，还是检测中断

设策略从观测 $o_t$ 预测长度为 $H$ 的动作块，实际执行其前 $h_t$ 步。**起点选窗**的方法先确定 $h_t$，随后开环执行该前缀，再获取新观测。它可以随场景变化选择不同长度，但不能在已选前缀内部识别突然滑移或目标移动。

BCP 正属于这一类。轻量 Transformer 一次输出所有候选窗口之间的继续概率，再将它们组合成有序的长度分布。“连续的 Bernoulli 决策”描述概率分解，并不意味着机器人每走一步都重新观察并询问是否继续。DEHP、EQRL、ChunkTrust 的执行窗口也在重规划点决定。

**执行中验证**则在动作队列尚未耗尽时读取当前观测，检查旧计划是否仍适用；偏差过大时丢弃尾部或启动新推理。SV-VLA、FFDC-WAM、VLA-Corrector 和事件触发推理属于这一方向。它们需要持续感知与额外判断，减少大模型调用的同时会引入验证成本。

例如，机器人已规划好 20 步搬杯动作。起点选窗可以因接近桌边而只执行 5 步；执行中验证还能发现第 3 步杯子被碰动，提前请求新计划。两者分别处理可预见的反馈需求与执行后才出现的信息。

## 3. 学习窗口：奖励究竟教会了什么

BCP 冻结动作生成器，以同一任务的多条轨迹学习窗口选择；固定窗口参考轨迹帮助衡量调用效率，成功轨迹还按相对调用数获得奖励。监督来自整条轨迹，同一个优势传递给其中多个窗口决策。它能学会在什么情形下多看一次更有利，但不能直接修复基础策略生成的错误动作。

DEHP 更早采用冻结生成器加长度头的接口。它用 PPO 和半马尔可夫折扣 $\gamma^h$ 处理不同窗口的持续时间，奖励侧重任务成功，没有显式调用惩罚。其验证对象是状态输入的 Diffusion Policy、仿真装配与插入，不能扩写成视觉 VLA 真机证据。[DEHP，§3–4](https://arxiv.org/html/2606.11408v2)

窗口学习也可以与行为内容耦合。EQRL 在冻结 VLA 上联合学习潜变量操控、去噪次数和执行长度，因而即使生成器权重不更新，输出行为仍会改变。ACSAC 用 Flow BC 提供候选，再由 causal Transformer critic 评估各候选的全部前缀，选择动作和长度。前者已有联合调度，后者已有前缀价值比较；“同时优化行为与窗口”本身不足以构成新的机制差异。ACSAC 的证据来自 OGBench 离线及离线到在线实验，也不宜直接移作 VLA 部署结论。[EQRL，§3](https://arxiv.org/html/2606.14375v1)；[ACSAC，§4](https://arxiv.org/html/2605.11009v2)

SparkVLA 则扩大了决策语义：Stop 表示当前子任务完成并请求高层新指令，正长度表示继续当前子任务。它以示范和 rollout 的完成边界构造排序偏好，训练评分头、上下文模块及高层 LoRA；selector 阶段冻结基础分支，不代表整个流程从未适配模型。选择器只在块边界运行。[SparkVLA，方法与执行附录](https://arxiv.org/html/2608.16172v1)

## 4. 用可靠性代理与预测后果选窗口

代理路线用容易计算的信号判断何时值得重新观察。AAC 看多样本动作熵，A³ 增加草稿验证，Knowing When to Stop 读取已有交叉注意力，PACE 与 Action Upcycling 从动作速度结构寻找边界。它们各自依赖“信号变化与动作可靠性相关”的条件；模型自洽或动作平滑都不自动保证物理执行正确。

“免训练”也不等于没有代价。AAC 默认多采样、A³ 还要重解码验证；PACE 的接受阈值由每任务训练示范校准。Action Upcycling 无需模型内部访问和额外采样；注意力方法则依赖可读取的模型内部结构。选择基线时，这些接口与成本差异会影响公平性。

ChunkTrust 同时利用生成过程的频谱变化和新旧动作拼接后的连续性，以 Beta 记忆保留当前 episode 的窗口偏好。这里的记忆由质量代理更新，并非由真实成败更新。可选 QHA 只学习这些证据构成的软标签，提供上下文相关先验；部署时仍保留即时证据计算，不是以任务奖励训练的 BCP 替代品。[ChunkTrust，§3–4、附录 A.6](https://arxiv.org/html/2609.39754v2)

CA³C 将比较推进到动作后果：多个动作候选使用共享随机噪声输入世界模型，依据预测未来的共识及变化位置选候选和窗口。它仍在执行前判断；世界模型的准备、微调和推理都应计入成本。共享噪声减少比较中的随机干扰，但比较的是不同动作的想象未来，并未直接测量“获取新观测后重规划”的实际收益。[CA³C，§3、附录 A.1](https://arxiv.org/html/2610.07949v1)

## 5. 真正读取新观测，需要付出什么

SV-VLA 每个控制步用新视觉和缓存高层特征预测参考动作，与队列动作比较；验证器由示范动作回归训练。FFDC-WAM 检查真实观测与想象未来的兼容性，其流程还包含 mixture-of-horizon 的生成模型训练。VLA-Corrector 通过学习的潜空间动力学检测执行漂移，触发后还引导下一次动作生成，作用超出单纯调度。

这些方法说明“看到偏差就中断”已有直接先例。它们的区别在于偏差相对什么参照、验证器怎样训练，以及触发后只是重规划还是还执行纠正。事件触发的 React When You Need To 进一步将新图像变化用于提前启动异步推理；其调用间隔还受生成延迟约束，不能直接当作同步控制中的 $h$。

效率指标也需要对齐。BCP 的 RoboTwin50 成功率由 89.88% 升至 93.94%，但表 4 调用数为 5.382→5.614，物理步数为 269.075→248.102；10.43→10.24 秒来自单次延迟与控制频率的合成估计。它支持更好的成功率与所估运行成本，不支持“相对基线调用更少”。验证方法报告的大模型调用数，还可能未包含辅助验证推理；评估应分别核对调用数、物理步数、额外计算与实际墙钟时间。[BCP，表 2、4](https://arxiv.org/html/2608.03483v1)

## 6. 更窄的研究问题与阅读顺序

在已有工作基础上，仍可提出一个具体假设：在能够恢复中途状态的仿真中，固定状态和剩余动作块，配对比较“立即重规划”和“继续旧块”的后续结果，用收益差监督中断决策，再研究它与动作生成训练的相互作用。这里需要辨别新反馈、重新采样和额外算力分别带来的收益。

这一设想与 BCP 的整轨迹信用不同，但还要面对 ACSAC 的多前缀价值比较：它已从 replay 奖励和 TD bootstrap 学习前缀预期回报。SEAR 也已有多前缀 TD，只是所读版本主要评估固定执行长度，并把自适应重规划留作后续。因此，更窄的差异是从同一中途状态实际执行两个分支所得的配对回报，而非泛泛地“学习重规划价值”。这仍是待检验假设；所读方法间的差异不能替代全领域新颖性核验。[ACSAC](https://arxiv.org/html/2605.11009v2)；[SEAR，§5.1、§6](https://arxiv.org/html/2603.01891v2)

建议先读 **BCP→DEHP** 理解长度头与信用分配，再读 **SV-VLA→FFDC-WAM／VLA-Corrector** 理解新反馈怎样进入控制环；随后用 **Action Upcycling→ChunkTrust→CA³C** 比较代理信号的成本，最后读 **EQRL→ACSAC→SEAR** 检查联合调度和局部价值学习的已有覆盖。若目标是长任务中的子任务切换，再加入 SparkVLA。
